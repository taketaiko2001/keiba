# keiba - 競馬仮想馬券シミュレーション記録

このリポジトリは、実際の金銭を伴わない**仮想の馬券購入シミュレーション**の記録用です。
原資100万円 → 目標120万円（1レースあたり仮想投資上限5,000円）を運用します。

- **実際の馬券購入・送金は一切行いません。** すべて記録上のシミュレーションです。
- 記録は [`競馬運用記録.md`](./競馬運用記録.md) に集約します。運用ルール、収支サマリー、レースごとの買い目・結果・反省をここに追記していきます。
- **対象範囲（2026-09-01〜）：トークン利用量節約のため、中央競馬(JRA)のみ・土日のみに縮小している。** 地方競馬(NAR)の予想・購入は一旦停止中。
- このリポジトリはクラウド定期ルーティン（RemoteTrigger）から定期的にチェックアウトされ、以下を行います。
  1. 直近数時間以内に発走予定のJRAレースを確認する
  2. 発走10分前までの間に、オッズ・過去成績・騎手調教師成績・追い切り評価等から見て妙味があると判断できるレースがあれば、仮想の買い目を確定し記録に追記する（発走時刻を過ぎたレースには購入しない）
  3. 過去に「仮想購入」したレースで結果がまだ未確定のものがあれば、結果を取得し、着順・払戻・収支・反省を記録に反映する
  4. 変更をコミットしてpushする
  - 実行間隔は毎正時07分・土日のJST 9-21時のみ（1ルーティンあたり最短1時間間隔というRemoteTriggerの制約による）。2026-08-31に一時的に、結果確認のみを行う軽量ルーティンを30分ずらして追加し実質30分間隔化を試したが、クラウド実行回数（利用コスト）が増えるため運用者の判断で1時間間隔に戻した（該当ルーティンは無効化して残置）。

## tools/ ディレクトリ（データ取得ツール）

netkeibaのページをWebFetch（要約AI経由）で読むと、表の列を読み違えて誤ったオッズを返すことが実測で確認されている（例：「人気順位」を「単勝オッズ」と誤答）。そのため、生HTMLを直接取得してBeautifulSoupで確実にパースするツールを用意している。

- `tools/netkeiba_fetch.py <race_id>` — 出馬表ページから馬番・馬名・horse_id・**性齢（年齢・性別）**・騎手・jockey_id・**調教師・trainer_id**・斤量（weight_carried_kg）・**馬体重と増減（body_weight_kg / body_weight_diff_kg）**・単勝オッズ・人気順を人気順にソートして取得する。horse_id は netkeiba_horse.py へ、jockey_id/trainer_id は netkeiba_people.py への入力に使える。
- `tools/netkeiba_result.py <race_id>` — 結果・払戻ページから着順・タイム・上がり3F・確定単勝オッズと、単勝/複勝/馬連/ワイド/馬単/3連複/3連単それぞれの払戻金・組み合わせ・的中人気を取得する。レース未確定の場合は `is_finalized: false` を返す。
- `tools/netkeiba_horse.py <horse_id>` — 馬個別ページから過去の全競走成績（日付・開催・着順・単勝オッズ・人気・騎手・斤量・**距離・馬場状態（馬場コンディション）**・タイム・着差・通過順位＝脚質の目安・上がり3F・馬体重増減・賞金）を新しい順に取得する。近走のフォーム分析、距離・馬場適性の判断に使う。既知の制約：JRA参戦歴がある馬など一部でテーブル列がずれ、レース名以降が正しく取得できないケースがある（要修正）。
- `tools/netkeiba_people.py <jockey|trainer> <id>` — 騎手・調教師の個別ページから、通算成績（累計）と当年成績（勝率・連対率・複勝率・騎乗/出走回数）を取得する。中央(JRA)・地方(NAR)の成績表が別々に存在する場合、出走回数が多い方＝主戦場の成績を自動選択する。買い目判断で「人気薄でも腕の立つ騎手・調教師なら浮上しやすい」を評価する材料に使う。

事前に `pip install -r tools/requirements.txt`（requests, beautifulsoup4）が必要。race_id は `YYYY`(4桁) + 場コード2桁（船橋43／笠松47／園田50など）+ 開催月2桁 + 開催日2桁 + レース番号2桁、の16桁。netkeibaのレースページURLから確認できる。

出力はJSON。標準出力にUTF-8で書き出すか、第2引数にファイルパスを渡せばそこに保存する。

**注意（クラウドルーティン向け）**：このクラウド実行環境はネットワークポリシーで netkeiba.com への直接接続が403ブロックされることが実測で確認済み。`tools/*.py` はローカル（ネットワーク制限なし）専用で、クラウドルーティンでは実行しないこと。クラウドでは WebFetch/WebSearch のみを使う。

## data/ ディレクトリ（Kaggle過去データ・分析、ローカル専用）

`data/` は `.gitignore` 対象でリポジトリには含まれない（500MB超のため）。Kaggle「[JRA日本中央競馬会 Horse Racing Dataset](https://www.kaggle.com/datasets/takamotoki/jra-horse-racing-dataset)」(1986-01-05〜2021-07-31、netkeibaスクレイピング由来、takamotoki氏作成)をローカルにダウンロードし、統計分析に使っている。取得には `pip install kaggle` と Kaggle APIトークン（`~/.kaggle/access_token`）が必要。

**分かったこと（2026-08-29時点の分析）**：161万件の全馬成績（着順・単勝オッズ・人気）を人気順位別に集計したところ、教科書的な「フェイバリット・ロングショット・バイアス」を確認した。1番人気の単勝回収率は約85.6%（控除率以上に割高）である一方、7〜11番人気の単勝回収率は100〜113%とほぼ均衡〜プラス圏（2010-2021年に絞るとより明確）。極端な人気薄(16〜18番人気)は35〜65%と大きく損。詳細は 競馬運用記録.md の反省・学びの蓄積欄を参照。**JRA(中央競馬)のデータであり、2026-09-01〜の仮想購入対象(JRAのみ)と母集団が一致するため、参考情報としての信頼性は高い**（2026-08-29時点では地方競馬(NAR)も対象で母集団が異なる注意書きだったが、現在はJRAのみに縮小したためこの注意は該当しない）。
